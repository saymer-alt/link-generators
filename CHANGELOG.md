- **Безопасный дефолт контроллера в VPS-профилях**: `vps-local` и `vps-gateway` теперь генерируют `external-controller: 127.0.0.1:9090` — раньше контроллер Mihomo (полное управление без секретного ключа) слушал `0.0.0.0:9090` и при открытом на VPS TCP/9090 был доступен снаружи. HWID от значения не зависит.

- **Allow LAN стал router-only** (deployment profiles): в `vps-gateway` чекбокс больше не остаётся доступным и не протекает из router-дефолта — раньше свежая страница с переходом в gateway-профиль молча выдавала `allow-lan: true` + `bind-address: "*"`, хотя transparent gateway принимает трафик через TUN + policy routing, а не через LAN-listener. Теперь в обоих VPS-профилях `Allow LAN` = OFF + disabled (UI-слой), а Build повторно применяет контракт независимо от DOM (tamper чекбокса в VPS не имеет эффекта; `allow-lan: true` возможен только в «Роутер / обычный TUN»). Ручное router-состояние чекбокса переживает визит в VPS-профиль и восстанавливается. Подсказка «?» обновлена; parity-сценарии vps-gateway описывают осознанную смену дефолта, контракт закреплён в tests/profile-matrix.cjs.
- Политики по доменам принимают вставленные правила mihomo с хвостовым `,no-resolve` у `IP-CIDR`/`IP-CIDR6`: раньше опция делала строку нераспознанной (префикс с «,no-resolve» не парсился как число), и политика, состоящая только из таких строк, молча пропускалась. Теперь `,no-resolve` срезается перед разбором (движок и так добавляет его всегда); другие опции (`src`) меняют семантику правила и по-прежнему отклоняются с предупреждением. Регрессия закреплена в web4core (`fix(dpr): accept trailing ,no-resolve on typed CIDR policy lines`, a8a722d).
- Отмена выбора в диалоге «📂 Загрузить .conf / .awg» больше не стирает ранее загруженные WG/AWG-профили (раньше открытие picker'а с последующей отменой молча очищало весь набор).
- Исправлен выбор provider-узлов с ведущими/хвостовыми пробелами в имени: resolver сначала ищет exact match, затем единственный `trim()`-эквивалент, а в Mihomo API всегда передаёт оригинальное имя byte-for-byte; неоднозначность и отсутствие совпадения завершаются ошибкой.
- Исправлена методология sweep/switchtest для персистентных WireGuard-хендшейков: полевые измерения показали, что после переключения dialer-группы старый транспорт может сохраняться более 150 секунд. `--fresh-handshake` выполняет reload изолированного тестового конфига через `PUT /configs?force=true`, ждёт API, повторно подтверждает выбранный узел и только затем снимает trace; без этого режима результат честно помечается как `unverified`.

### Verified

## [1.4.0] - 2026-09-19
