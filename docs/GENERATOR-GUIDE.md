# Короткая инструкция по генератору

Короткая человеческая инструкция: как за пару минут получить рабочий конфиг.
Технические подробности — по ссылкам в конце.

## 1. Сначала выберите, где будет работать Mihomo

Первый вопрос наверху вкладки Builder: **«🎯 Где будет работать Mihomo?»**

### 🏠 Роутер / обычный TUN (Keenetic) — по умолчанию

Mihomo работает на домашнем роутере и поднимает TUN-интерфейс: весь трафик
устройства идёт через него. Профиль включает TUN, MIPS stack, Mixed Port 7890
и Allow LAN — все параметры потом можно менять вручную.

### 🖥️ VPS — локальный Mihomo / SOCKS для Xray / 3X-UI

На VPS уже работает Xray/3X-UI (или другое приложение), которое отправляет
трафик в Mihomo через `127.0.0.1:7890`. Профиль выключает TUN, MIPS и Allow LAN
(внешний доступ к 7890 не нужен) и оставляет только локальный SOCKS-вход.
Схема: `Xray/3X-UI → 127.0.0.1:7890 → Mihomo → proxy`.

### 🌐 VPS Transparent Gateway (amnezia-mihomo-gateway)

Специальный сценарий: transparent-gateway с Linux policy routing / iptables /
Docker / AmneziaWG. Генератор создаёт **только Mihomo-часть** (TUN `tun-mihomo`,
DNS-перехват fake-ip, `auto-route: false`); Linux routing и firewall настраивает
[amnezia-mihomo-gateway](https://github.com/saymer-alt/amnezia-mihomo-gateway).
Для обычного VPS с Xray/3X-UI используйте предыдущий профиль.

Подробности: [VPS-GATEWAY.md](VPS-GATEWAY.md).

## 2. Входные данные

В поле «Основные прокси-ссылки / URL-подписки» вставьте:

- обычные прокси-ссылки: `vless://`, `trojan://`, `ss://`, `masque://`… — напрямую;
- ссылки на подписки (HTTP(S) URL) — при включённом режиме «URL-подписки»;
- можно смешивать: подписка + обычные ссылки.

WARP-конфиги: вкладка **⚡ WARP MASQUE Links** генерирует `masque://` ссылки —
кнопка «🚀 В Mihomo Builder» переносит их сюда. WireGuard/AmneziaWG — кнопка
«📂 Загрузить .conf / .awg»: каждый файл станет отдельным WireGuard-прокси.
Повторное нажатие **добавляет** файлы к уже загруженным (не заменяет!);
загруженное видно списком с удалением по одному и кнопкой «🧹 Очистить все».

## 3. Основные переключатели

| Переключатель | Что делает |
|---|---|
| 🛡️ TUN Interface | Системный TUN: весь трафик устройства через Mihomo. Нужен на роутере; на VPS с локальным Xray — выключен. |
| ⚡ MIPS stack | Стек обработки TUN-трафика (не процессор!). По умолчанию MIPS; требует Mihomo ≥ 1.19.31, иначе gVisor. |
| 🔌 Mixed Port 7890 | Локальный HTTP+SOCKS вход Mihomo. |
| 🌐 Allow LAN | Доступ к Mihomo из локальной сети (добавляет `bind-address: "*"`). На VPS — выключать. |
| 🖥️ Web UI | Веб-дашборд управления (MetaCubeXD) на порту 9090. |
| ⚙ Расширенный TUN stack | `system`/`mixed` — экспериментальные; обычно достаточно MIPS/gVisor. |

## 4. Подписки

Режим «📡 Использовать URL-подписки» превращает HTTP(S) ссылки в `proxy-providers`:
Mihomo сам скачивает и обновляет списки узлов (раз в 12 часов + health-check).

- **🚫 Exclude Filter** — regexp по именам узлов подписки: совпавшие узлы
  исключаются. Важно: regexp сравнивается с **фактическим именем** узла.
  Латинский `ru|russia` не совпадёт с кириллическим «Россия» — для таких
  подписок пишите кириллический вариант (`Россия|Москва`). Семантика
  provider-level vs group-level: [MIHOMO.md](MIHOMO.md).
- **📱 Device Model** — необязательный заголовок `x-device-model` для панели
  подписки.
- Некоторые панели (например, Geodema/Remnawave) требуют заголовок **`x-hwid`** —
  генератор добавляет его автоматически; без него панель может вернуть
  заглушку «App not supported» вместо списка узлов.

## 5. WARP/WireGuard через dialer-proxy

В карточке WireGuard можно указать **промежуточный proxy (dialer-proxy)**:
WireGuard/WARP-туннель будет устанавливаться через другой прокси или группу
(«туннель в туннеле»). Так WARP подключается к Cloudflare из сети другого
узла/страны.

Два полевых факта:

1. **Промежуточный узел должен реально поддерживать UDP relay.** Рабочие
   сайты/TCP через узел сами по себе не означают, что через него поднимется
   WireGuard/WARP. Проверяется только фактическим тестом.
2. **Переключение узла в dialer-группе — не мгновенная смена пути.** Уже
   установленный WireGuard-хендшейк может держать старый transport path дольше
   150 секунд. Для гарантированной смены пути нужен пересоздание outbound
   (reload конфига/перезапуск Mihomo). Смена colo Cloudflare — наблюдение,
   не гарантия: Cloudflare выбирает ingress сам.

## 6. ADVANCED Per-Proxy

Секция «ADVANCED — Отдельный вход на каждый прокси» по умолчанию свёрнута.
Внутри: режим, создающий отдельный TUN/SOCKS-вход **для каждого** прокси.
Для обычного использования не нужен. Раскрытие секции ничего не включает —
включается только явный master-переключатель.

## 7. Кнопки

- **⚡ Build Config** — собрать YAML и автоматически проверить структуру;
- **📋 Copy YAML** — скопировать результат (после успешной проверки);
- **📂 Загрузить .conf / .awg** — импорт WireGuard/AmneziaWG профилей;
- **🚀 В Mihomo Builder** (вкладка WARP) — перенос сгенерированных ссылок в Builder.
