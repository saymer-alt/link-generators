# WARPSCOUT на Keenetic / Entware — пошаговая инструкция для новичка

> **Цель:** установить WARPSCOUT на роутер, найти **реально работающие** WARP/AmneziaWG endpoint'ы, проверить их качество и сохранить конфигурацию выбранного подключения.
>
> Идите сверху вниз. Каждая команда в обязательных шагах **самостоятельная**: не нужно заранее задавать переменные вроде `JT`. Команды рассчитаны на SSH-консоль Keenetic с установленным Entware. Проверено по реальному логу установки WARPSCOUT 0.16.0 на aarch64; успешное прохождение сети зависит от провайдера и не гарантируется.

**Короткий маршрут:** шаги **1–5** — установка, аккаунт, скан AWG, оценка и готовый конфиг. Шаг 6 — если нужен другой узел Cloudflare. Шаги 7–9 — необязательная диагностика и MASQUE. Не нужно выполнять все варианты подряд, если результат уже устраивает.

## 0. Перед началом

Нужно:

- Keenetic/Netcraze с **работающим интернетом**, установленным и запущенным **Entware**, возможностью зайти по SSH.
- Несколько свободных мегабайт на `/opt` и достаточный запас оперативной памяти. Для первого запуска используем только **4 параллельных туннеля** (`-jt 4`).
- Понимать, что **WARPSCOUT — сканер**. Он не переключает автоматически маршрутизацию Keenetic и не устанавливает найденный туннель для всех устройств. Найденный конфиг позже нужно отдельно применить в нужном клиенте.

Команды вводите **в SSH-консоли роутера**, не в командной строке Windows. После каждого шага смотрите результат, и только потом переходите к следующему.

## 1. Установить WARPSCOUT

Скопируйте **всю** команду установки целиком:

~~~sh
opkg update && opkg install curl ca-bundle && curl -fSsL https://raw.githubusercontent.com/saymer-alt/entware-go/gh-action-build/warpscout/install.sh | sh
~~~

Установка завершилась успешно, если видите сообщения вроде:

~~~text
WARPSCOUT 0.16.0 is ready
WARPSCOUT installation complete.
~~~

Номер версии может отличаться. Сообщение `Unknown package 'warpscout'` **само по себе не является ошибкой**: установщик умеет перейти к загрузке IPK из GitHub release. Ориентируйтесь на **конечный** результат установки, а не на промежуточные сообщения.

При установке WARPSCOUT может сразу зарегистрировать WARP-аккаунт. Сообщения `API unreachable directly` и ошибки relay не означают окончательный отказ: установщик пробует дополнительные способы регистрации. Если в конце написано `Registered fresh WARP account`, аккаунт уже получен.

**Не запускайте повторную регистрацию просто из-за промежуточной ошибки API.**

## 2. Перейти в каталог WARPSCOUT и проверить готовность

Выполните команды **по очереди**:

~~~sh
mkdir -p /opt/etc/warpscout
~~~

~~~sh
cd /opt/etc/warpscout
~~~

~~~sh
warpscout version
~~~

Проверка аккаунта:

~~~sh
ls -lh /opt/etc/warpscout/warpscout-account.json
~~~

- **Файл есть, размер не нулевой** — переходите к шагу 3. После успешной автоматической регистрации ничего больше делать не нужно.
- **`No such file or directory`** — выполните в этом каталоге:

~~~sh
cd /opt/etc/warpscout
warpscout register
~~~

После успешной регистрации снова проверьте файл командой `ls` выше.

Важно: `warpscout-account.json` — **имя файла**, а не команда. Его не нужно запускать. В нём находятся приватные данные; **не копируйте содержимое в чаты, отчёты и GitHub**. При каждом новом SSH-сеансе перед сканами вновь делайте `cd /opt/etc/warpscout`, поскольку аккаунт ищется в текущем каталоге.

## 3. Первый настоящий скан: AmneziaWG (AWG)

Для фильтрованных сетей начнём с **AWG**, а не с обычного WireGuard. Флаг `-gen-i1 quic` генерирует маскировку первого пакета AWG; это **не** означает, что вы сканируете MASQUE H3.

Выполните **одну** команду:

~~~sh
warpscout scan -p awg -P -jt 4 -gen-i1 quic -o awg-first-report.txt -conf warp-awg.conf
~~~

Что она делает:

- `-p awg` — сканирует WARP через AmneziaWG.
- `-P` — проверяет передачу данных внутри туннеля, ping и потери; отсеивает соединения, которые поднялись и затем были оборваны.
- `-jt 4` — не более четырёх одновременных туннельных задач (число указано прямо в команде).
- `-gen-i1 quic` — пробует сгенерированную маскировку первого пакета.
- `-o awg-first-report.txt` — сохраняет подробный отчёт.
- `-conf warp-awg.conf` — **в том же скане** создаёт конфиг для выбранного программой лучшего рабочего endpoint'а, если такой найден.

Скан с `-P` может длиться долго, особенно на роутере. Дождитесь **итоговой таблицы или сообщения об ошибке**; отсутствие немедленного результата не означает зависание.

### Как понять, что получилось

В итоговой таблице и отчёте обращайте внимание на:

| Поле | Что искать |
|---|---|
| `WORKING` / работающие | Есть реально работающие endpoint'ы |
| `TUN PING` / `LOSS` | По возможности **0% потерь**, затем меньшую задержку внутри туннеля |
| `torn down` | Нежелательные варианты: туннель поднялся, но передачу данных оборвали |
| `NODE` / `NODE LOCATION` | Узел Cloudflare, через который фактически прошла проверка |
| `SEEN AS` | Наблюдаемая географическая/сетевая информация о выходе — **не гарантия нужной страны для конкретного сервиса** |
| `ENDPOINT PING` | Задержка до адреса снаружи, сама по себе **не доказывает**, что туннель передаёт данные |

Хороший кандидат: **WORKING, не torn down, LOSS 0%, приемлемый TUN PING и подходящий NODE**. «Самый низкий ping» без проверки узла и потерь — ещё не окончательный выбор.

Проверьте, что файлы созданы:

~~~sh
ls -lh awg-first-report.txt warp-awg.conf
~~~

Чтобы увидеть только выбранный адрес без показа секретного ключа:

~~~sh
grep -i '^Endpoint[[:space:]]*=' warp-awg.conf
~~~

**Не публикуйте `warp-awg.conf`**: в нём приватный ключ и параметры туннеля. Если не создан конфиг — сначала смотрите итог скана, возможно, рабочих endpoint'ов не нашлось. Файлы при повторном запуске с теми же именами могут быть перезаписаны; для сохранения разных результатов используйте новые имена.

## 4. Что получилось в результате

Если шаг 3 прошёл успешно, уже есть:

1. `awg-first-report.txt` — подробный отчёт, из которого можно выбирать и сравнивать адреса.
2. `warp-awg.conf` — готовый **нативный AWG-конфиг для выбранного endpoint'а**.

Это **результат работы WARPSCOUT**, а не доказательство, что выбранный endpoint уже работает в production Mihomo или в системном VPN Keenetic. Для применения используйте клиент, который поддерживает формат и указанные параметры AWG, и отдельно проверьте реальный выход и маршрутизацию.

Если первый endpoint подходит — **основной сценарий закончен**. Не нужно выполнять все дальнейшие варианты.

## 5. Нужен другой узел Cloudflare? Например, исключить DME

Если в таблице много `DME`, а задача — найти путь **без этого узла**, запустите **отдельный скан с фильтром**:

~~~sh
warpscout scan -p awg -P -jt 4 -gen-i1 quic -exclude-node DME -o awg-no-dme-report.txt -conf warp-awg-no-dme.conf
~~~

В этом примере программа не выбирает `DME`. Сравните результат с первым сканом; при успехе появится `warp-awg-no-dme.conf`. **Если с фильтром ничего не найдено, это не повод считать первый скан нерабочим**: фильтр мог исключить все доступные пути.

Для другого окружения (например, когда нежелателен `ARN`) команда аналогична, **но применять фильтр следует только если он нужен вашей задаче**:

~~~sh
warpscout scan -p awg -P -jt 4 -gen-i1 quic -exclude-node ARN -o awg-no-arn-report.txt -conf warp-awg-no-arn.conf
~~~

Можно исключить сразу несколько узлов через запятую: `-exclude-node DME,ARN`. Не включайте оба запрета без причины — так выборка становится меньше.

**Не путайте NODE с выходной страной.** Например, `-exclude-country RU` исключает пути через узлы соответствующей страны в понимании WARPSCOUT, но не гарантирует, что сервис перестанет определять выход как `RU`. Узел Cloudflare может меняться со временем, даже если IP endpoint'а остался тем же.

## 6. Хотите проверить скорость, а не только задержку? Необязательно

Обычный скан ранжирует прежде всего по ping. Если важнее скорость скачивания, используйте дополнительную фазу `-speed`:

~~~sh
warpscout scan -p awg -P -jt 4 -gen-i1 quic -speed -best-by speed -o awg-speed-report.txt -conf warp-awg-speed.conf
~~~

Это **отдельный, более длительный** скан с передачей тестовых данных. Результат зависит от текущего uplink и нагрузки; не воспринимайте его как гарантированную будущую пропускную способность. Если необходимо исключить узел, добавьте к этому же скану подходящий `-exclude-node`.

## 7. Если AWG не нашёл ничего рабочего

**Не переустанавливайте WARPSCOUT и не пересоздавайте аккаунт без причины.** Сначала попробуйте другую маскировку I1, выполняя команды по одной:

~~~sh
warpscout scan -p awg -P -jt 4 -gen-i1 dns
~~~

~~~sh
warpscout scan -p awg -P -jt 4 -gen-i1 stun
~~~

~~~sh
warpscout scan -p awg -P -jt 4 -gen-i1 random
~~~

Если рабочий вариант найден, повторите именно **успешный** скан с `-o ИМЯ_ОТЧЁТА -conf ИМЯ_КОНФИГА` (как в шаге 3), чтобы получить его конфиг, а не случайно записать результат другого профиля.

Если варианты I1 не помогли, WARPSCOUT может подобрать параметры сам:

~~~sh
warpscout find-junk -jt 4 -gen-i1 random
~~~

Далее используйте **параметры, которые напечатает программа**, для полноценного `scan -P`. Успех подбора параметров ещё не заменяет проверку реального data path.

### Обычный WireGuard — только для сравнения

На сетях без жёсткой фильтрации можно проверить обычный WARP/WG:

~~~sh
warpscout scan -p wg -P -jt 4 -o wg-report.txt -conf warp-wg.conf
~~~

Это отдельный протокол: результат AWG **не доказывает**, что plain WG работает. На фильтрованных российских сетях WG нередко не проходит, поэтому для первого практического результата выше выбран AWG.

## 8. Альтернатива: MASQUE H2 (TCP) или H3 (QUIC)

Этот раздел **не нужен**, если AWG уже решил вашу задачу. MASQUE полезно тестировать, если требуется другой транспорт или не проходит AWG.

Для MASQUE сначала **ищут SNI**, затем **подтверждают полноценным сканом с тем же SNI**. Успешный `find-sni` сам по себе не доказывает, что трафик проходит: это наблюдалось в наших полевых тестах H3.

### Вариант A — MASQUE H2 / TCP

Шаг A1. Поиск подходящего SNI:

~~~sh
warpscout find-sni -p masque-h2 -jt 4
~~~

Шаг A2. Из вывода **вручную выберите SNI с лучшим результатом**. В примере ниже используется `www.apple.com`, **только как иллюстрация**: **замените его в команде на SNI, найденный на вашем роутере сейчас**.

~~~sh
warpscout scan -p masque-h2 -P -jt 4 -masque-sni www.apple.com -o masque-h2-report.txt -conf warp-masque-h2.yaml -conf-type mihomo
~~~

Если рабочие endpoint'ы нашлись, YAML сохранится в `warp-masque-h2.yaml`. Для этого профиля будет указан `network: h2`.

### Вариант B — MASQUE H3 / QUIC

Шаг B1. Найти SNI:

~~~sh
warpscout find-sni -p masque -jt 4
~~~

Шаг B2. **Замените `cdn.jsdelivr.net` на лучший SNI из вашего вывода** и выполните полноценный скан:

~~~sh
warpscout scan -p masque -P -jt 4 -masque-sni cdn.jsdelivr.net -o masque-h3-report.txt -conf warp-masque-h3.yaml -conf-type mihomo
~~~

H3 сканируется через `-p masque`, H2 — через `-p masque-h2`. Они могут вести себя совершенно по-разному на одном WAN.

**Важно:** если `find-sni` показал успех, а последующий `scan -P` сообщает `no MASQUE endpoint passed data`, транспорт **не прошёл полноценную проверку**. Не записывайте этот SNI как рабочий. Другой SNI или другой uplink может дать иной результат.

Исторические `www.apple.com`, `www.google.com`, `cdn.jsdelivr.net` и `4pda.to` **не универсальны** и не должны подменять самостоятельный поиск.

## 9. Как использовать результат в link-generators

Откройте [WARP & Mihomo Unified Generator](https://saymer-alt.github.io/link-generators/).

### Если получили AWG `.conf`

`warp-awg.conf` — конфигурация **AmneziaWG**, а не MASQUE. Не вставляйте её в поле **WARP MASQUE Links** как MASQUE YAML. Для сборки Mihomo используйте соответствующий импорт WG/AWG в **Mihomo Config Builder** и проверьте поддержку сгенерированных WARPSCOUT параметров, результат валидации и работоспособность готового конфига на целевом устройстве.

### Если получили MASQUE `.yaml`

1. Откройте вкладку **WARP MASQUE Links**.
2. Откройте локально `warp-masque-h2.yaml` или `warp-masque-h3.yaml`, скопируйте **содержимое файла** в поле импорта (не публикуйте ключи).
3. Нажмите **«Распарсить»**; если появится выбор нескольких кандидатов, выберите нужные и нажмите **«Импортировать выбранных»**.
4. Проверьте сообщение импорта и поля **Advanced MASQUE**: для WARPSCOUT/Mihomo YAML с `proxies:` и `type: masque` современный генератор импортирует **identity, подходящий SNI и точный найденный `server:port`** для соответствующего транспорта. У выбранного точного endpoint'а приоритет над встроенной стратегией/списком портов.
5. Если YAML содержит только **legacy WARP identity без распознанного MASQUE proxy**, генератор использует **другую семантику**: identity импортируется, а transport/endpoint подбираются самим генератором. Не путайте эти два сценария.

Для H2 по **встроенной** стратегии проект применяет Safe Ports Only (`443, 8443, 4443, 8095`), **но импортированный точный WARPSCOUT endpoint имеет приоритет** и может использовать другой порт. Это ожидаемо; если вам принципиально нужны только safe ports, выбирайте совместимый endpoint сознательно и проверяйте конечный результат.

**Граница ответственности:** WARPSCOUT подтверждает свой тестовый туннель. После сборки в генераторе всё равно нужна проверка конечного Mihomo-конфига, реального маршрута и доступности нужного сервиса. Нельзя считать поле `NODE` или `SEEN AS` гарантией географии выхода в будущем.

## 10. Если что-то пошло не так

| Сообщение / симптом | Что делать |
|---|---|
| `Unknown package 'warpscout'` | Если далее есть успешная загрузка IPK, `WARPSCOUT ... is ready` и `installation complete` — **ничего исправлять не требуется**. |
| `API unreachable directly` или ошибка relay | Проверьте, получен ли аккаунт в конце установки. Если файл аккаунта отсутствует — из каталога в шаге 2 выполните `warpscout register`. |
| `-sh: warpscout-account.json: not found` | Не запускайте имя файла как команду. Проверяйте существование через `ls -lh /opt/etc/warpscout/warpscout-account.json`. |
| `invalid value "" for flag -jt` | Была передана пустая переменная. В этой инструкции **везде указано числом `-jt 4`**. |
| `Using cached WARP account` | Нормально: программа нашла зарегистрированный аккаунт. |
| Нет `warp-awg.conf` после скана | Проверьте итог скана: конфиг лучшего endpoint'а нельзя получить, если подходящие рабочие варианты не найдены. |
| Результат `0 working` / `torn down` | Попробуйте другой I1 (шаг 7), затем H2 с подбором SNI (шаг 8); проверьте текущий WAN и маршруты. |
| `No working endpoints found` после `-exclude-node` | Уберите фильтр, посмотрите полный список. Фильтр **не создаёт** альтернативные маршруты. |
| `find-sni` успешен, но MASQUE `scan` не передаёт данные | Считайте результат неподтверждённым, повторите с другим SNI / uplink. |
| WARPSCOUT не находится через `PATH` | Проверьте, что Entware запущен и доступен `/opt/bin`; попробуйте `/opt/bin/warpscout version`. |

## 11. Что сохранить для следующего сравнения

Запишите **без приватных ключей** модель роутера, версию KeeneticOS и WARPSCOUT, WAN/провайдера, дату, протокол, способ маскировки/SNI, `WORKING`, `TUN PING/LOSS`, `NODE`, `SEEN AS` и выбранный `IP:port`. Не публикуйте `warpscout-account.json`, `warp-*.conf`, MASQUE YAML с `private-key` или необезличенные журналы.
