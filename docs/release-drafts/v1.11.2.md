# v1.11.2 — ручной GLOBAL и автоматические группы приоритетов

В версии **1.11.2** исправлена маршрутизация при включённом Tiered Failover в `mode: rule`.

## Главное

Раньше генератор переписывал `MATCH,GLOBAL` в `MATCH,🪜 TIERED-AUTO`. В результате переключение `GLOBAL` в панели Mihomo не влияло на трафик, попавший в это последнее правило, хотя автоматическая Tiered-группа отображалась внутри `GLOBAL`.

Теперь правило остаётся **`MATCH,GLOBAL`**, а `🪜 TIERED-AUTO` находится **первым участником** ручной группы `GLOBAL`:

```yaml
proxy-groups:
  - name: GLOBAL
    type: select
    proxies:
      - "🪜 TIERED-AUTO"
      - REJECT
      # остальные уже имевшиеся группы/выходы, если они есть
rules:
  - MATCH,GLOBAL
```

Это **схематичный фрагмент**, не готовый конфиг и не перечень всех автоматически созданных участников.

## Пользовательский сценарий

При выборе `🪜 TIERED-AUTO` действует автоматическая политика приоритетов (выход из строя → резерв → возвращение). В панели Mihomo можно явно выбрать другой **имеющийся** участник `GLOBAL` или `REJECT` и затем вернуться к Tiered root. Новая версия **не добавляет `DIRECT`** в список ручных выходов без твоего решения.

## Совместимость

- При выключенном Tiered генератор выдаёт тот же YAML, что и версия 1.11.1 в сравниваемых сценариях.
- С включённым Tiered меняется лишь окончание `MATCH`: прежнее `MATCH,🪜 TIERED-AUTO` заменяется на `MATCH,GLOBAL`. Доступность реального прокси на конкретном VPS от этого не гарантируется.
- Существующие сохранённые YAML со старым `MATCH,🪜 TIERED-AUTO` не мигрируют сами собой: нужно пересобрать конфиг либо проверить и исправить маршрут вручную. Проверяйте `GLOBAL.proxies` и фактический выбор в контроллере.
- DPR `RULE-SET`-маршруты, явно направленные в другие группы, продолжают использовать собственные селекторы; изменение `MATCH` не превращает GLOBAL в универсальный перехват всех правил.

## Проверки

- RED-before → GREEN-after для дефекта #279.
- Браузерные тесты Builder/DPR/Tiered, Project Save/Load, Config Studio, Firefox/WebKit и регрессии изменения DNS/WG.
- Реальные бинарники Mihomo **1.19.31** и **1.19.32** в отдельной синтетической loopback-лаборатории: ручное переключение `GLOBAL`, автоматический переход между эшелонами, возврат и `REJECT`.
- Byte parity при Tiered OFF; при Tiered ON допускается исключительно согласованная дельта `MATCH`.

**Границы доказательства:** это контролируемые TCP/HTTP runtime-тесты, не полевое подтверждение UDP, MASQUE H3, DNS-leak-free и клиентского dataplane на реальном VPS/роутере. Серверные конфигурации и работающие устройства не менялись.
