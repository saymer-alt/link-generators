## Аудит #322 «восстановить получение серверов из подписки» (31.10.2026)

**Исправлено в коде (RUNTIME-PROVEN на синтетических подписках):**

- Ручной путь без DevTools (#323): кнопка «🌐 Открыть JSON Mihomo» (top-level, без secret/query), три шага, точные 401/403/404 и честный сетевой отказ.
- Видимая отмена (#328): «⏹ Пропустить» — `AbortController` обрывает всю цепочку direct/fallback (движковая поддержка signal — web4core#27); раньше бюджет бросал гонку, а сеть продолжала скрытые попытки до ~90 с.
- Бюджет и изменение ввода тоже останавливают сеть; FAILED/отмена показывают «количество узлов неизвестно» (UNKNOWN ≠ 0), без автоматических повторов.
- Сборка provider YAML работает без preview; preview остаётся opt-in.
- Контракты Worker GET/POST живы (проверка агента 31.10 из своей сети, синтетические URL: HTTP 200, 0.2–0.5 с) — self-test без приватных данных.

**Внешние зависимости (не код генератора):**

- Прямой запрос к подписке без `Access-Control-Allow-Origin` блокируется браузером — на клиенте неустранимо, обход только через Worker.
- Строгий v2-preview требует развёрнутого Worker с `strict-same-origin-v1` (источник готов, деплой — owner dispatch).

**FIELD-UNKNOWN (не объявлять решённым):**

- Причина `ERR_CONNECTION_CLOSED` из сети владельца 27.10: недоступность `*.workers.dev` (типичная SNI-блокировка) — HYPOTHESIS, не доказана; из сети агента Worker отвечает.
- Работает ли полный preview из сети владельца после #328 — не проверялось; реальные HWID-gate подписки и подсчёт устройств сервисом — не проверялись.
- Chrome Local Network Access / `targetAddressSpace` для локального контроллера — отдельный PoC, не v1.12.

**Вывод:** полевая приёмка #322 (шаги плана owner-проверки с реальной подпиской в сети владельца) обязательна до пометки issue решённым.

## План ручной проверки владельцем (без риска для работающего роутера)

1. Открыть `index.html` из `main` (локально file:// или черновой Pages preview), убедиться: в шапке видны «🔑 Идентичность подписки (Mihomo Builder)» и маска HWID.
2. «👁 Показать HWID» → полный ID; повторный клик скрывает; «📋 Копировать HWID» → буфер.
3. «➕ Другое устройство» → переключение в шапке; собрать тестовый конфиг (Sub Mode ON, синтетическая подписка) → `x-hwid` в YAML соответствует выбранному устройству; после смены устройства — баннер STALE.
4. Подготовить переносимый v2: «🔐 Подготовить переносимый проект v2» (подтвердить предупреждение о секретах) → назначить второй подписке отдельный HWID → «💾 Сохранить проект». Проверить шапку: «Проект v2 · подписок: N · переносимых HWID: M · без HWID: K», локальный HWID скрыт; смена устройства в шапке — тост «назначения не изменены», YAML после пересборки не меняется.
5. Загрузить v2-файл на другой машине/в чистом профиле → реестр браузера не изменился → Build → провайдеры несут сохранённые HWID (A=H1, B=C=H2).
6. «Получить список» на недоступной подписке → «⏹ Пропустить» → статус «количество узлов неизвестно», сеть обрывается; сборка provider YAML работает и без списка.
7. `# provider-name: Имя` перед URL → имя в MetaCubeXD.
8. На отдельной копии конфига в Mihomo (не на рабочей): `mihomo -t` + запуск, ручной GLOBAL → Tiered → fallback → ручной GLOBAL.
