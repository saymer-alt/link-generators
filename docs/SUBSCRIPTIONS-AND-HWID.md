# Подписки, HWID и получение списка серверов

Практическая инструкция для выпущенного **Link Generators v1.12.0** и последующих
совместимых сборок. Начните с [быстрого старта](../quick-start.html), если нужен
обычный конфиг из одной ссылки; этот документ — для HTTP(S)-подписок.

## Главное: обычному пользователю нужен режим v1

- **Одна подписка на одном роутере:** оставьте локальный режим **v1**, ничего
  специально не настраивайте. Генератор создаёт один стабильный HWID для
  выбранного логического устройства и повторно применяет его при следующих
  сборках. **Не нажимайте «🎲 Сменить ID» при обычном обновлении YAML**:
  коммерческий сервис может посчитать новый HWID дополнительным устройством.
- **Несколько роутеров из одного браузера:** в верхней панели «🔑 Идентичность
  подписки (Mihomo Builder)» выберите нужное устройство или нажмите
  «➕ Другое устройство» **перед Preview/Build**. Шапка показывает замаскированный
  HWID; «👁 Показать HWID» и «📋 Копировать HWID» — явные действия.
  После смены устройства старый Build помечается устаревшим (STALE).
- **У одного конфига несколько подписок с разными уже закреплёнными HWID:**
  только тогда полезен опциональный **переносимый проект v2**, описанный ниже.
  Включать его всем пользователям не нужно.

**Device Model** — читаемое имя в `x-device-model` для запросов просмотра
подписки; это **не замена** HWID и изменение имени не регистрирует новое устройство.

## URL-подписка и обычная proxy-ссылка — разные режимы

На вкладке **⚙️ Mihomo Config Builder**:

| Вход | «📡 Использовать URL-подписки» | Результат |
|---|---|---|
| HTTP(S) URL подписки | Включено (по умолчанию) | `proxy-providers`, далее сам Mihomo обновляет подписку |
| Обычная `vless://` / `trojan://` / `ss://` ссылка | Выключено, если нет URL-подписки | Статический `proxies` |
| HTTP(S) подписка при выключенном режиме | Выключено | **Build скачивает подписку в браузере** и однократно встраивает её узлы в `proxies`; при недоступности Build не проходит |

В режиме URL-подписок (`Sub Mode ON`) **Build не обязан получать имена узлов**.
Сгенерировать provider-YAML можно без просмотра подписки. Напротив, в режиме OFF
для встраивания удалённых узлов в конфиг запрос необходим.

### Понятные имена провайдеров

Поставьте комментарий **непосредственно перед URL подписки**:

```text
# provider-name: Основная подписка
https://example.invalid/subscription-a

# provider-name: Резервная подписка
https://example.invalid/subscription-b
```

Имена используются для `proxy-providers` и отображаются, например, в
MetaCubeXD. URL и содержимое подписки от этого не меняются. Если комментария
нет, генератор выбирает имя автоматически. Пустое имя, две директивы подряд
или директива перед обычной proxy-ссылкой вызывают ошибку, а не тихое
переименование. Показанные адреса — учебные, не настоящие подписки.

## Получить список узлов или продолжить без него

1. Включите «📋 Показать серверы подписки» и явно нажмите **«📋 Получить список»**.
   До этого в `Sub Mode ON` Build **не делает запрос за списком**.
2. Появится список известных имён. **Галочка исключает сервер**, а не включает
   его. Ручное поле `Exclude Filter` дополняет галочки. Счётчики отражают только
   полученные имена — это не гарантия доступности или полного состава подписки.
3. Если запрос завис или не нужен, нажмите **«⏹ Пропустить»**. Отмена обрывает
   текущую цепочку сетевых запросов. Ошибка/таймаут/отмена означают
   **«количество узлов неизвестно»**, а не «в подписке 0 серверов».
   В `Sub Mode ON` можно **собрать YAML без Preview**.
4. При сетевой блокировке прямого обращения (CORS, браузерная защита локальной
   сети, Mixed Content, недоступность Worker) используйте
   **«📡 Импорт узлов из работающего Mihomo (runtime)»**:
   укажите адрес контроллера, нажмите «🌐 Открыть JSON Mihomo», скопируйте
   JSON из новой вкладки и нажмите «📋 Вставить JSON» либо загрузите файл.
   Это **только список имён для Exclude Filter**, а не изменение рабочего
   `config.yaml`. Не вставляйте API secret в URL.

Запрос списка напрямую из браузера может быть заблокирован политикой CORS.
Резервный запрос через Cloudflare Worker передаёт его инфраструктуре URL и
заголовки `x-hwid`/`x-device-model`, а также ответ сервера подписки,
который может содержать секреты. Если такая передача неприемлема, не включайте
удалённый Preview. Контроллер собственного Mihomo через Worker **не проходит**.
Подробно: [DATAFLOW.md](DATAFLOW.md).

**Полевое ограничение v1.12.0:** получение списка из домашней сети владельца
подтверждено; предыдущее `ERR_CONNECTION_CLOSED` в рабочей сети не доказывает
ошибку текущей версии и там ещё требует повторной проверки.

## Опционально: переносимый проект v2 с разными HWID

Это **не новый протокол подписок и не обязательный способ сборки**.
Он нужен, если в **одном** Mihomo YAML есть несколько коммерческих подписок,
каждая из которых уже закреплена у провайдера за своим HWID, либо если нужно
сохранить эти назначения для переноса на другой ПК.

1. В режиме URL-подписок вставьте две или больше подписок.
2. Раскройте **«🔑 Идентичность подписки»** и нажмите
   **«🔐 Подготовить переносимый проект v2»**. Подтвердите предупреждение о
   том, что экспортируемый файл может содержать настоящие HWID, URL с токенами
   и приватные ключи.
3. В панели **«🔗 HWID каждой подписки (проект v2)»** оставьте основной HWID
   первой подписке; второй назначьте **существующий HWID** («📥 Импортировать
   введённый HWID») либо создайте случайный **только если нужен новый слот
   устройства**. Для открытого Gist/публичного источника можно выбрать
   **«Без HWID — Gist / открытая подписка»**.
4. Нажмите **Build Config**, проверьте `proxy-providers`: у каждой защищённой
   подписки свой `header.x-hwid`; у «Без HWID» такого заголовка нет.
5. **«💾 Сохранить проект»** создаёт `.lgproject.json` v2. При импорте на
   другом компьютере привязки сохраняются, **локальный реестр HWID браузера
   не перезаписывается**. Смена устройства в шапке также не перепривязывает
   идентичности активного v2-проекта.

В шапке v2 показаны счётчики подписок/переносимых HWID/источников «без HWID»,
а кнопки раскрытия **локального** HWID не показываются. Для возвращения к
обычному режиму предусмотрена команда «Вернуться к локальному HWID (v1)»:
перед этим сохраните v2-проект, иначе его индивидуальные назначения
будут потеряны в текущей рабочей сессии.

**Секреты:** `.lgproject.json` может содержать HWID, ключи и токены
подписок. Не прикладывайте его целиком к Issues, не публикуйте как Gist и
не передавайте как «безопасный экспорт». Для проверки используйте синтетические
адреса и HWID, чтобы случайно не занять слоты коммерческого тарифа.

**Ограничение v1.12.0 при выпуске:** генерация v2 YAML проверена, но
строгий удалённый Preview требует отдельно развёрнутой политики Worker
`strict-same-origin-v1`. Пока Worker не обновлён, такой Preview
**намеренно отказывает (fail-closed)**; это не означает, что Build v2
сломался. Не обходите этот отказ передачей секретов в сторонние сервисы.

## Границы и диагностика

- `mihomo -t -f config.yaml` проверяет синтаксис/поддержку полей, но не
  подтверждает живой handshake, UDP, DNS, firewall или отсутствие утечек.
- Сохранённый проект — это настройки **генератора**; импорт проекта не
  запускает и не перенастраивает роутер или VPS.
- Обеспечение запрета прямого выхода пользовательского трафика с публичного
  VPS (issue [#286](https://github.com/saymer-alt/link-generators/pull/286))
  **не является новой гарантией v1.12.0**; служебная загрузка подписок через
  `proxy: DIRECT` и user-egress — разные задачи.
