## Детали по пунктам

### 1. Visual Routing Graph — PARTIAL

Реализовано: Config Dependency Graph (#140, v1.9→v1.11) строит фактический граф из конфига (rule/provider/group/proxy/dns узлы, typed edges, referential integrity, no speculation); Domain Coverage показывает путь домена до цели с `runtime-selected` пометками; Rule Provider Explorer — инвентарь провайдеров.

Не реализовано: графический (нетекстовый) рендер графа. Формулировки про «красивую картинку» в v1.9 сознательно были вторичны («сначала корректная модель фактов») — модель готова, рендер не начат.

Классификация осталась PARTIAL: рендер — кандидат v1.12+, но решение за владельцем после UI field-test v1.11.

### 2. DNS ↔ Routing consistency — PARTIAL

EVENING-02 (2026-10-08) добавил DNS path intelligence для Physical Topology: next-hop resolve-at-source (SOURCE-PROVEN, ProxyServerHostResolver), destination — только по явной декларации `node.dns.destination`, иначе UNKNOWN. Для обычного Builder-конфига destination-DNS-анализатор не написан: нужно исследовать interaction `dns.enhanced-mode` (fake-ip/redir-host) × rules × sniffer — это отдельная задача с доказательной базой.

Кандидат v1.12+ (требует SOURCE-PROVEN исследования Mihomo DNS-модуля; не реализовывать без него).

### 3. What-if / dry-run — DONE

Physical Topology: `ptSimulateTopology` (CHAIN_UNAVAILABLE при отказе узла, никакой авто-перестройки). Config Studio: правки применяются только в памяти через replay-модель; «Применить изменения» не пишет на диск; экспорт gated статической валидацией. Документы: PT-GENERATION.md, PT-NETWORK-DIAGNOSTICS.md.

### 4. Semantic Trace — DONE

Три уровня: value trace (Explainability UX, v1.9), path trace (Domain Coverage, v1.9/v1.11), physical trace (`ptTraceTopology`, v1.11 — INTENDED vs RUNTIME-OBSERVED разделение жёстко зафиксировано).

### 5. Dead/unused dependency diagnostics — DONE

`csDiagnostics` (CS-UNUSED/CS-DANGLING-REF/CS-DUP-NAME/CS-GROUP-CYCLE) + Rule Provider Explorer unused/missing + Routing Inspector duplicates/shadowed. Тесты: dependency-graph 16, config-import 11, rule-provider-explorer 25+51.

### 6. Provider provenance/freshness — PARTIAL

Есть: provider identity в графе и Runtime Import; наблюдения без TTL. Нет: формальная freshness-модель, история наблюдений, дедупликация. Дизайн подготовлен в NIGHT-FUTURE-01: `future/WARPSCOUT-REVALIDATION.md` (наблюдения endpoint'ов) и `future/KNOWN-SERVICES-PROVENANCE.md` (происхождение записей). Реализация — owner decision (v1.12+ candidate).

### 7. Tiered Failover UX — DONE

#182 (2026-10-07): явная «＋ Добавить», hint «выбор ещё не добавляет», дубликат-выход warning-lint, дефолт «Резервные выходы», rejected-WG dismiss, compact controls, mobile. Остались только визуальные вопросы для owner UI field-test (не редизайн).

### 8. Legacy accessibility improvements — PARTIAL

Сделано: aria-label/aria-pressed/aria-live на новых контралах (Runtime Evidence, Config Studio, PT), focus-visible для summaries/footer, single-disclosure маркеры (#192/#193), mobile 320–480 матрица в browser-тестах.

Не сделано: сквозной keyboard-only проход по всему приложению, экранная читалка (screen reader) тесты, контрастный аудит. Кандидат v1.11-polish (безопасный, низкорисковый) — требует owner решения.
