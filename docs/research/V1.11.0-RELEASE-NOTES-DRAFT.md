**Черновик, не опубликован.** Интегрировано в main; production остаётся v1.10.0. OWNER GO #207 выполнен, но promotion/tag/release не разрешены. До публикации требуется owner UI/device acceptance и отдельное решение владельца.

## Основные изменения относительно v1.10.0

- **Config Studio 2.0:** bounded YAML import, редактор рабочей копии с явным редактированием секретов, diff/export, диагностика зависимостей и маршрутов.
- **Project Save/Restore:** versioned project сохраняет поддерживаемое состояние Builder; Preview/Cancel/Confirm/Undo. YAML Reverse объясняет EXACT/DERIVED/MISSING/UNSUPPORTED/CONFLICT вместо скрытого изменения смысла.
- **DNS ↔ Routing Intelligence:** интегрировано через #207. Проверяет respect-rules/PSNS, resolver fragments/policy arrays, first-match/PASS и direct/global boundaries. CONFIRMED относится к структурному контракту; INFERRED/UNKNOWN ограничивают выводы о маршрутах. Не изменяет source/Builder и не наблюдает реальные DNS leaks.
- **WG/AWG и deployment profiles:** независимые профили и dialer chains, Gateway DNS OFF/TUN preservation, проверки missing/cyclic targets, согласованность DPR/Tiered/AWL.
- **Visual Routing Graph и Physical Topology:** граф конфигурации и owner-declared topology, объяснение зависимостей/ограничений, per-node artifacts и bounded runtime evidence. Статический граф не выдаётся за наблюдаемый маршрут.
- **Надёжность и безопасность:** исправлены rollback карточек при повторном render failure, поздние imports, runtime timeout, secret Reset и stale Build rejection; secret-safe labels, XSS/input boundaries, улучшены длинные поля и responsive UI.

## Ограничения

YAML Reverse не обещает восстановить отсутствующие subscription/fallback URLs, произвольный direct URI emitter, Per-Proxy listeners, arbitrary unsupported YAML или custom Tiered multi-URL health-check. Raw keepalive ranges и compatibility25 не эквивалентны. Runtime group/provider choice и непрозрачные GEO/rule sets остаются UNKNOWN. Реальные CORS/subscriptions, устройства владельца и WAN/WG/UDP handshakes требуют отдельной проверки. Parse acceptance и loopback traffic не заменяют её.
