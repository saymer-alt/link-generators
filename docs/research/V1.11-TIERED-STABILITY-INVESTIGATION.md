## Подтверждённые дефекты harness

- `until` подавлял исключения, не сохранял ответ, код соединения и состояние core.
- H создавал `s2` без stop/finally. Последующие сценарии выполнялись с лишним core;
  успешный `process.exit(0)` не завершает независимый дочерний процесс.
- Failure/watchdog завершали Node без общей очистки mocks/health/restart core.
- Listen Promise не отвергал bind error; core logs были неограниченными.
- **RUNTIME-PROVEN, Windows:** TCP-only `freePort` выбрал mixed-port 54117,
  входящий в UDP exclusion 54064–54163. Core сохранил живой controller и ROOT=T1,
  но сообщил `listen udp ... bind ... forbidden by its access permissions` и не
  поднял mixed listener. Независимый UDP bind дал EACCES; TCP exclusion list этот
  диапазон не содержит. Отказ случился в H контролируемого late-health run,
  не в исходном Linux A. Его JSON и FAIL сохранены. `freeMixed` теперь резервирует
  и проверяет UDP+TCP на одном loopback-порту, затем освобождает их перед spawn.
  Unit regression доказывает, что TCP-only accepts UDP-occupied port, dual rejects.

Утечка H происходит **после** A и не объясняет исходное падение A внутри того же запуска.
Изменения ограничены наблюдением и lifecycle test infrastructure, без изменения генератора,
YAML semantics, ожиданий priority/partial/failover/failback и бюджета A.

## Воспроизведение

`MIHOMO_BIN`, `JS_YAML_PATH` должны указывать на проверенный core и js-yaml 4.1.0.
`node tools/tiered-stability/repeat.cjs 20 <output-directory>` выполняет независимые
запуски с новыми каталогами/процессами/портами. Failures считаются и не повторяются.
Сохраняются JSON per run, bounded core tail, timeline, HTTP responses/errors,
health observations, counters и проверка закрытия core/controller/mixed ports.
Отдельный ограниченный CI workflow запускает 10 samples/version и сохраняет artifacts
даже при failure. Он не добавляет повторов к неуспешному Generator CI job.

Controller GET snapshots не запускают delay/health probes; `/version`, mixed readiness,
ROOT selection, mock health и фактический T1 response фиксируются отдельно.
Выборочная диагностика добавляет небольшую стоимость наблюдения; это не побитовая
реплика первоначального execution timing.

## Первичные выводы о причинах

- `last=false` исходного A доказывает минимум один завершённый predicate с body,
  отличным от T1A/T1B. Одни только исключения всех запросов оставили бы `last=undefined`.
  Позднейшие исключения могли подавляться; HTTP status/body неизвестны.
- Прямой причинный переход от утечки H к предшествующему A того же run исключён.
- Windows UDP exclusion даёт другой signature: mixed ECONNREFUSED и last=undefined.
  Нельзя объявлять это причиной исходного Linux last=false.
- Late-health probe на 31: actual T1 до первого успешного health check,
  ROOT=T1 и leaf alive=true при пустой history; ответы health задержаны на 800 ms
  сверх health timeout 500 ms. `alive=true` и выбор группы не доказывают completed health.
- Небольшое различие latency версий в выборке не доказывает version regression.

Продуктовые index/runtime/YAML semantics не изменены. ROOT CAUSE UNKNOWN сохраняется.
