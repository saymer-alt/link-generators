## 3. Независимая проверка пяти дефектов Codex

Все пять воспроизведены Codex на #192, независимо перепроверены на объединённом main прямыми пробами (не через codex-тесты):

1. **Cyclic YAML aliases** — `csLoadBounded('a: &x\n  b: *x')` → `CS-LIMIT: циклические YAML aliases не поддерживаются`; легальная вложенность <64 принимается, >64 отклоняется.
2. **Rename в правилах** — rename A→A2 обновляет правило ровно один раз (`DOMAIN,x.example,A2`), счётчик вхождений точен.
3. **Logical rule target** — `AND,((…),(…)),A` → цель заменена, результат остаётся корректным YAML-скаляром строки правила.
4. **Dangling refs** — rename/update переносит ссылки; delete с зависимостями fail-closed (REFS / REFS-RULES / flow-отказы).
5. **Multiline PT label** — label с `\nexternal-controller: 0.0.0.0:9090` → PT-BAD-ID (управляющие символы), генерация артефактов отказана (artifacts пусты); injection в YAML невозможен.

## 7. Security assumptions

- Секреты контроллеров и config-credentials — memory-only вкладки; проверено негативными тестами (body text, URL, storage).
- Документ-aware redaction (WeakMap по документу) применяется ко всем автопоказываемым текстам (сводка/trace/diff/диагностики).
- Внешние endpoint'ы контроллеров пользователь вводит сам; генератор не ходит в сеть без явного действия, не создаёт туннели/файрволы.
- Все фикстуры — синтетические (RFC5737, example.invalid, dummy-ключи). Реальных owner-материалов в репозитории нет.
