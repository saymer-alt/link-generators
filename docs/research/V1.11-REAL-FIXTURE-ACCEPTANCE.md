## Project и Reverse: разные результаты

Project путь: Build → Save download → новый browser context → Load Preview → Cancel без mutation → Load Confirm → field equality → byte parity repeated Build → изменения sources/WG/dialer/TUN/DNS/WebUI → Build → Undo. После удаления профиля сравниваются beans оставшихся; unrelated health/device/MTU/DNS/DPR/Tiered сохранены.

YAML путь: Parse → Preview без mutation → Cancel → source-config evidence equality → loss acknowledgment → Confirm/Build/Undo для восстановимого subset. Полный сценарий 6 subscriptions+8 mixed WG/AWG →8+7 выполняет qa-reverse-integration. Stale snapshots, rapid actions, rollback fault injection и secret edit/hide/save — existing independent suites.

Ограничения:

- Direct non-WG nodes не сериализуются обратно в URI. Сохраняются в source-config evidence, новый Build их не переносит.
- Sub OFF URL и AWL fallback URL отсутствуют в YAML. Для AWL missing fallback автоматическая повторная сборка не объявляется успешной; нужны исходный проект/источник либо осознанная ручная смена режима.
- Tiered использует собственный фиксированный health endpoint. Вместе с custom general health в YAML несколько URL: Reverse показывает CONFLICT и блокирует Apply; Project Restore остаётся exact. Это текущая ограниченная модель Reverse, не новый parser failure.
- Per-Proxy listeners не восстанавливаются: Build без TUN/SOCKS отклоняется; тест явно включает SOCKS перед дальнейшей сборкой, это ручное изменение, не parity. Server-list split, исходные WG filenames/formatting, произвольные nested fields не обещаются восстановленными. Unknown data сохраняется в проекте как parsed evidence, не merge в Build.
- Общая parity независимого серверного YAML не доказана. Source-preserving Studio editor остаётся путём сохранения произвольных sections/rules/groups.

## Подтверждённый новый дефект / ремонт

**P2 — восстановленный WG dialer ссылается на исключённый direct proxy.** Место: `index.html:rbYamlToProject`, ветка non-WG passthrough. Минимум: static VLESS `SYNTH-VLESS` + WG/AWG `dialer-proxy: SYNTH-VLESS` → Build → YAML Reverse. До ремонта Preview давал UNSUPPORTED для VLESS, но разрешал Apply; после Apply Build становился NOT_BUILT из-за отсутствующей цели. Expected: CONFLICT до применения, без смены target и без потери исходных данных.

Причина: классификация потерянных direct nodes не учитывала входящие WG dialer dependencies. Fix: если восстановленный WG target входит в список непереносимых direct node names, добавить CONFLICT, который штатный Preview guard блокирует. Ни direct-link emitter, ни новая нормализация целей не добавлены. Regression: case awg-dialer проверяет реальный Build, exact Project Restore, source evidence и disabled Confirm при этой зависимости. До фикса test воспроизвёл NOT_BUILT; после подтверждён fail-closed Preview. Соседний WG→WG multi-level dialer и обычные gateway/router modes проверяются отдельно.

**P2 — web VALID для недопустимого emitted WG IPv4.** `validateMihomoYaml`: imported Address 999.999.999.999/999 → emitted ip 999.999.999.999; baseline web VALID, реальный Mihomo1.19.31 exit1 (invalid address). WireGuard не входил в обычную server/port branch и имел только key checks. Fix проверяет emitted IPv4 существующим rdIsIPv4 плюс canonical octets, без нового protocol parser; применяется существующий checkPort для flat WG endpoint. Negative WG cases не повреждают project state, соседние valid WG/AWG/deployment modes сохраняются. Port70000 baseline web принимал; Mihomo31 -t тоже принимает его — поэтому reject web по контракту1..65535 не объявляется доказательством parser reject или успешного endpoint runtime. Это демонстрирует границу -t.
