## Рекомендованный порядок (если владелец GO на v1.12)

1. **DNS↔Routing Intelligence** — самый дешёвый путь в production: чистая функция, есть точка интеграции (Config Studio `csDiagnostics` / Builder), риски ограничены ложными срабатываниями, тест-план §7 готов.
2. **MRS viewer (read-only)** — фундамент доказан байт-в-байт; основная работа = zstd-decode + производительность (rank/select-кэши) + UI-обёртка. Начать с research-страницы вне production bundle.
3. Всё остальное — по мере появления FIELD-OBSERVED данных (WARPSCOUT-наблюдения, инцидент-снимки): без них v1.14-темы остаются PoC.

## Общие правила (наследуются из future/README.md)

- Никаких изменений production bundle/CI без отдельного решения владельца.
- PoC живут в `research/poc/` — офлайн, синтетика, без сети и секретов.
- INFERRED/UNKNOWN-границы честно документируются в каждом документе; PoC-результат не «продвигает» себя в production автоматически.
