## Граф: масштаб, доступность и lifecycle

Начальный режим — Fit, без увеличения небольшого графа выше 100%. Диапазон всех действий 5–250%, кнопки изменяют масштаб на 25 процентных пунктов с ограничением на границах. Нижняя граница5% позволяет вместить высокую схему на мобильном экране; отдельный floor25% для кнопок ошибочно увеличивал масштаб при «−» после малого Fit — этот случай воспроизведён и исправлен. Малые подписи при обзоре ожидаемы: есть 100%, Focus и полная текстовая альтернатива. Существующий лимит отображения **60 nodes** не изменён; для документа со 100+ nodes сохраняется сообщение о truncation и доступен Focus. Fit вписывает текущий отображаемый граф, включая focused view.

У обоих consumers одинаковые кнопки с aria-label, индикатор масштаба с aria-live и keyboard activation. Builder теперь действительно заполняет свою существовавшую текстовую альтернативу. Focus-select исключён из build fingerprint: навигация не делает YAML STALE. Render заменяет старые обработчики через AbortController и отключает ResizeObserver; Clear также удаляет state с предыдущим документом. Нет глобальных pointermove listeners или внешней zoom-библиотеки.

Испытаны 3-node, точный **19-node / 31-edge** fixture, 50/100 proxies с прежним лимитом отображения, длинные имена, секрет в имени/credential, повторный Parse/Focus и malformed input. Некорректный Studio Parse сохраняет явно обозначенный предыдущий рабочий документ; Clear удаляет SVG и отключает controls. Обычный Builder Build с 19 proxies проверен отдельным E2E, затем действия навигации проверены без изменения YAML. Реальный pan мышью проверен в обоих consumers. Viewport: desktop 1280×850, mobile 320/360/390×740. Скриншоты desktop и 320px просмотрены.

Физические touch-устройства и аппаратный trackpad отдельно не испытывались; обработчики используют Pointer Events, pointer capture и touch-action только внутри SVG.

## Дополнительные дефекты, обнаруженные при review

1. **API JSON error → ложный успех.** `applyRuntimePayload` показывал parse error, после чего fetch безусловно писал success. Теперь parser application возвращает boolean, success появляется только после успешного применения.
2. **Незаполненная Builder text alternative.** `renderVrgBuilder` не передавал существующий output ID; теперь передаёт `vrgTextAltOut`, с прежней redaction до усечения.
3. **Visual focus / lazy Explorer search → ложный STALE.** Read-only controls находились в build fingerprint; создание поля поиска при раскрытии Explorer меняло fingerprint даже без изменения настроек. В полном локальном прогоне это остановило Inspector coexistence test. Все controls внутри read-only `routingDiagnostics` исключены из fingerprint; регрессия проверяет раскрытие и поиск, сохранение current snapshot и YAML.
4. **Очистка навигации.** Старый state после Studio Clear мог удерживать документ. Clear удаляет WeakMap entry, listeners и observer; тест проверяет отсутствие entry.
5. **Shared controller normalizer.** Новый default не распространяется на пустой/пробельный Physical Topology endpoint: перед общей нормализацией сохраняется явный NOT_CHECKED guard. Secret на невыбранный endpoint не отправляется.
6. **Click-only mutation при async Build.** На первом PR head `0ab781192f4a38578d7327e1c80ba112fb8c47cf` barrier-probe удержал ответ synthetic подписки, добавил политику реальным click и затем освободил ответ. Старый Build опубликовал YAML без добавленной карточки и отметил его fresh: **0/1 FAIL**, evidence сохранён. Теперь fingerprint проверяется после последнего subscription await, до внутренних preview/list render effects; перед публикацией также проверяется generation sequence. Старый Build не перезаписывает YAML. Тот же probe: **1/1 PASS**. Это guard жизненного цикла, generation/routing semantics не меняются.
