# Своя подписка через GitHub Gist

Этот вариант подходит, когда VPS и панель **3X-UI уже есть**, серверы/клиенты уже настроены, но не хочется использовать встроенную подписку панели.

Идея простая: создать **Secret Gist** на GitHub, положить туда обычные клиентские ссылки по одной на строку и использовать `Raw`-ссылку на файл как URL своей подписки.

> [!IMPORTANT]
> **Secret Gist — не настоящий приватный файл.** Он не показывается в поиске и Discover, но любой человек, получивший URL, сможет его открыть. Поэтому ссылку на Gist/Raw нужно считать секретом и не публиковать. Если нужна строгая авторизация и контроль доступа, используйте другой способ хранения подписки.

## Что понадобится

- аккаунт GitHub;
- уже настроенный VPS/3X-UI или другой источник клиентских ссылок;
- клиент, умеющий загружать подписку по HTTP(S) URL;
- ссылки вида `vless://`, `vmess://`, `trojan://`, `hysteria2://`, `tuic://`, `ss://` и т. п.

## 1. Соберите ссылки на серверы

В 3X-UI откройте нужный inbound/клиента и скопируйте **клиентскую ссылку подключения**.

В итоговом файле каждая ссылка должна находиться на отдельной строке, например:

```text
vless://UUID@example.com:443?security=reality&type=tcp#SE-VLESS
trojan://PASSWORD@example.net:443?security=tls&type=grpc#EE-TROJAN
hysteria2://PASSWORD@example.org:8443/?sni=example.org#DE-HY2
```

Это только пример формата. Используйте свои реальные ссылки, созданные вашей панелью.

Не нужно копировать в Gist весь конфиг 3X-UI, SSH-ключи VPS, пароли панели или другие административные данные.

## 2. Создайте Secret Gist

1. Откройте [gist.github.com](https://gist.github.com/) под своим аккаунтом GitHub.
2. В поле **Gist description** можно написать, например, `My proxy subscription`.
3. Задайте имя файла, например:
   - `subscription.txt`
   - `servers.txt`
   - `mihomo-sub.txt`
4. Вставьте ссылки на серверы — **по одной ссылке на строку**.
5. В меню кнопки создания выберите **Create secret gist**.

GitHub называет такой Gist `secret`: он не появляется в публичном поиске, но доступен любому, кто знает ссылку.

Официальная справка GitHub: <https://docs.github.com/en/get-started/writing-on-github/editing-and-sharing-content-with-gists/creating-gists>

## 3. Получите Raw-ссылку

Откройте созданный Gist и нажмите кнопку **Raw** у файла с подпиской.

Для подписки удобнее использовать стабильный URL без привязки к конкретной ревизии:

```text
https://gist.githubusercontent.com/USERNAME/GIST_ID/raw/subscription.txt
```

где:

- `USERNAME` — ваш GitHub username;
- `GIST_ID` — идентификатор Gist;
- `subscription.txt` — имя файла внутри Gist.

Если после нажатия **Raw** в адресе присутствует длинный SHA между `/raw/` и именем файла, это ссылка на конкретную ревизию. Для постоянно обновляемой подписки используйте вариант без SHA, как в шаблоне выше.

## 4. Добавьте URL в клиент или наш Mihomo Builder

Получившийся Raw URL можно использовать как обычную HTTP(S)-подписку.

Для нашего генератора:

1. Откройте **Mihomo Config Builder**: <https://saymer-alt.github.io/link-generators/>.
2. Вставьте Raw URL Gist в поле с серверами/подписками.
3. Оставьте включённой опцию **«Использовать URL-подписки»**.
4. Соберите `config.yaml`.

Mihomo будет получать список серверов по URL, а вам не придётся каждый раз заново собирать конфиг после изменения списка узлов.

## 5. Как обновлять подписку

Когда нужно добавить, удалить или заменить сервер:

1. откройте свой Gist;
2. нажмите **Edit**;
3. измените список ссылок;
4. нажмите **Update secret gist**;
5. обновите подписку в клиенте/Mihomo.

Стабильный Raw URL менять не нужно — он остаётся тем же, а содержимое файла обновляется.

## Пример структуры

```text
vless://...#Sweden
vless://...#Estonia
trojan://...#Germany
hysteria2://...#Finland
```

Главное правило: **один URI подключения — одна строка**.

## Если серверов много

Gist может содержать несколько файлов. Например:

```text
main.txt
backup.txt
test.txt
```

У каждого файла будет собственная Raw-ссылка. Это удобно, если нужно разделить основной, резервный и тестовый наборы серверов.

## Важные замечания по безопасности

- Не публикуйте Raw URL в открытых чатах, issue, README или публичных конфигурациях.
- Считайте URL подписки секретом: клиентские URI обычно содержат UUID, пароли или другие данные доступа.
- Secret Gist **не имеет полноценной защиты паролем**. Знание URL достаточно для чтения.
- Если ссылка утекла, безопаснее заменить клиентские ключи/UUID/пароли на серверах и создать новый Gist/новый набор URI.
- Не храните в такой подписке административные учётные данные 3X-UI, root/SSH-ключи и API-токены.

## Коротко

Схема выглядит так:

```text
3X-UI / VPS
    ↓
копируем клиентские URI
    ↓
Secret GitHub Gist
    ↓
Raw URL
    ↓
Mihomo / Hiddify / Happ / другой клиент
```

Это простой способ вести собственную подписку вручную, не включая и не публикуя встроенную подписку 3X-UI.
