# Config Studio 2.0: восстановление проекта и изменение конфигурации

Дата: 2026-10-09 (DAY-01). Для версий v1.11.0-dev. Всё работает локально в браузере, без сети и без сохранения куда-либо.

## Два источника — две гарантии

| | Проект `.lgproject.json` | Готовый `config.yaml` |
|---|---|---|
| Что это | Полный слепок Builder на момент «Сохранить проект» | Итоговый YAML (проект в него не входит) |
| Точность | **Точное восстановление** всего: подписки (дословно, с порядком), WG/AWG с ключами и именами файлов, все настройки | **По доступным признакам**: подписки (URL+порядок), WG/AWG-профили (ключи функциональны, имя файла — UNKNOWN), настройки по маркерам |
| Чего не восстановить | — | URL развёрнутых подписок (если Sub Mode был выключен), имена исходных файлов |

YAML Reverse **не без потерь** — студия показывает честный отчёт до подтверждения.

## Сценарий 1: сохранить проект и вернуться позже

1. Соберите конфигурацию в Builder (подписки, WG/AWG, настройки).
2. Нажмите **«💾 Сохранить проект»** — скачается `mihomo-project-….lgproject.json`.
   ⚠️ В файле приватные ключи и токены подписок — не передавайте его никому.
3. В любой момент (в том числе после закрытия браузера): **«📂 Загрузить проект»** → выберите файл → Builder восстановлен.
4. Нажмите обычный **«⚡ Build Config»**.
5. Передумали? **«↩︎ Отменить восстановление»** возвращает состояние до загрузки.

## Сценарий 2: восстановить из готового config.yaml

1. Вкладка **«🔎 Config Studio»** → вставьте YAML → **«🔎 Разобрать»**.
2. Появится **«🔁 Восстановить в Builder»** → нажмите — увидите **предпросмотр**:
   - счётчики: подписки / WireGuard / AmneziaWG / DPR-политики / Tiered-карточки;
   - ключевые настройки (профиль, TUN/MIPS, WebUI, allow-lan);
   - статусы: `EXACT` — восстановится точно; `DERIVED` — с нормализацией; `MISSING` — восстановить невозможно (например, URL развёрнутых подписок); `UNSUPPORTED` — Builder не имеет такого представления (сохранено в проекте и исходном YAML; новый Build это НЕ переносит); `CONFLICT` — данные противоречивы;
   - сравнение «было → станет» с текущим Builder.
3. Предпросмотр не меняет Builder. Для потерь подтвердите отдельный чекбокс; CONFLICT/INVALID блокируют применение. Нажмите **«Подтвердить восстановление»** либо **«Отмена»**. Изменение YAML или Builder делает предпросмотр устаревшим — создайте его заново.
4. После подтверждения Builder восстановлен; **«↩︎ Отменить восстановление»** возвращает прежнее состояние. Ошибка применения откатывает изменения. Затем меняйте источники штатными средствами → **«⚡ Build Config»**.

## Изменение состава источников

После любого восстановления источники — это обычные поля Builder:
- **Подписки**: строки в поле ввода — добавляйте/удаляйте/меняйте URL и порядок.
- **WG/AWG**: карточки профилей — удаление (✕), замена файлом, режим «напрямую/через прокси» и таргет.

Ничего второго «мини-Builder» внутри Studio нет: источник истины один.

## Секреты

- В редакторе Studio секретные поля скрыты; **👁** показывает текущее значение (это ваш ключ — вы вправе его видеть), повторное нажатие скрывает.
- Пустое секретное поле = «оставить исходное значение». Вписали новое — заменилось.
- Hide/Reveal меняет только видимость: введённое значение сохраняется до Save или отмены редактирования. Переключение без ввода не создаёт правку.
- Ключи никогда не попадают в дифф, статусы, отчёты и тосты. В скачанном YAML и проекте они есть — иначе конфиг не работал бы.

## Ограничения (честно)

- YAML Reverse из конфига с развёрнутыми подписками: исходные URL невосстановимы; прямые прокси-узлы переносятся в отчёт (в Builder их пока нельзя представить ссылкой).
- Веб-валидация не заменяет `mihomo -t` — финальная проверка настоящим Mihomo остаётся за вами.
- Подробная техническая карта обратимости: `docs/research/REVERSE-BUILD-RECOVERABILITY.md`.
