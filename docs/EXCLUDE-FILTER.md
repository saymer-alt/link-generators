# Mihomo `exclude-filter`: практическая проверка

`Exclude Filter` в Mihomo Builder передаётся в каждый HTTP `proxy-provider` как поле `exclude-filter`. Значение сопоставляется с **фактическим именем узла в подписке**, поэтому язык и формат имени имеют значение.

## Почему `ru|russia` может не сработать

Полевой тест 2026-10-01 на Mihomo v1.19.31 и реальной Geodema/Remnawave-подписке показал, что пример `(?i)ru|russia` не удалил ни одного российского узла: их имена были кириллическими, например `🇷🇺 Россия Москва` и `🇷🇺 Новосибирск (xhttp)`.

Для таких подписок нужно включать варианты, которые реально встречаются в именах. Например, как ориентир можно использовать:

```text
(?i)ru|russia|россия|🇷🇺
```

Это **пример, а не универсальный пресет**: перед применением смотрите фактические имена узлов конкретного provider. Если подписка использует только названия городов без страны/флага, добавьте нужные варианты явно.

## Что проверено

На выборке Geodema baseline содержал 99 узлов. Контрольные тесты дали:

- `Россия|Новосибирск` → удалено ровно 6 RU-узлов, false positive = 0, false negative = 0;
- `Германия` → удалено ровно 3 немецких узла;
- exact-name фильтр → удалён ровно 1 выбранный узел;
- `Россия|Новосибирск|Германия` → удалено ровно объединение 9 узлов;
- после удаления фильтра полный baseline восстановился;
- reload конфига применял новый `exclude-filter` сразу, без обязательного чистого cache/home.

То есть механизм `exclude-filter` в генераторе и Mihomo v1.19.31 работает; прежний эффект «RU-фильтр не работает» объясняется несовпадением regexp с фактическими именами узлов, а не поломкой provider-фильтра.

## Provider-level и group-level

Генератор использует provider-level `exclude-filter`: исключённые узлы исчезают из самого provider и поэтому не попадают через `use:` в `⚡ Fastest` и `GLOBAL`.

Group-level фильтр — отдельная семантика Mihomo: provider продолжает содержать полный набор, а фильтруется только представление узлов внутри конкретной группы.
