## 2. SUBSCRIPTION PREVIEW (#152)

Предусловие: в поле ввода есть URL-подписка, чекбокс «📋 Показать серверы подписки» включён.

### 2A. Успешный preview и refresh
1. Нажать «📋 Получить список». PASS: кнопка на время запроса «Загрузка…», затем вернулась в
   «📋 Обновить список»; появился список имён; сводка вида «preview: N/N · найдено узлов: X».
2. Нажать «📋 Обновить список» повторно. PASS: список обновился без залипания.

### 2B. Stale-защита (race fix)
1. Нажать «Получить список» и НЕ дожидаясь, ввести символ в поле подписок (или Exclude Filter).
2. PASS: кнопка немедленно вернулась в idle; появилась строка «Список устарел — нажмите
   „Обновить список“»; старые имена НЕ применились (список пуст/прежний, а не подменён).
3. FAIL (кнопка осталась в «Загрузка…» навсегда) → зафиксировать — это регрессия #152.

### 2C. UNKNOWN ≠ 0
1. Временно указать заведомо недоступную подписку (например дописать несуществующий хост) и
   нажать «Получить список».
2. PASS: «preview: 0/N · количество узлов: неизвестно» (НЕ «найдено узлов: 0»); предупреждения
   с `[URL hidden]`, без URL/токена.
3. Вернуть рабочую подписку.

### 2D. Filter union + resizable
1. Отметить галочками 1–3 узла → PASS: обе сводки согласованы (верхняя «исключается: N ·
   останется: M», нижняя «исключено: N · после фильтра: M»), без расхождения.
2. Ввести в Exclude Filter ручной regex (например `(?i)ru|russia`) → PASS: union посчитан без
   double-count (узел под regex И галочкой считается один раз).
3. «Снять все» → PASS: остался только вклад regex; правка regex НЕ стирает список имён.
4. Потянуть нижний край списка узлов вверх/вниз → PASS: высота меняется, содержимое скроллится;
   сборка/YAML не меняются (после изменения высоты Build не требует перезапуска).

## 4. MIHOMO RUNTIME IMPORT (#159)

Предусловие: работающий Mihomo с provider-подписками; доступ к его external-controller.

### 4A. Определить адрес контроллера
1. В конфиге работающего Mihomo найти `external-controller: <host:port>` (это user-supplied
   адрес; в этом документе никаких конкретных IP не приводится).
2. Убедиться, что он слушает интерфейс, доступный с машины с браузером (не только
   `127.0.0.1`), и что контроллер НЕ выставлен в WAN.

### 4B. Прямой запрос из браузера
1. Generator main → блок «📋 Показать серверы подписки» → details «📡 Импорт узлов из
   работающего Mihomo».
2. Ввести адрес (допустимые форматы: `host:port`, `http://host:port`, `https://host:port`).
3. При необходимости ввести API secret (поле пароля; он НЕ сохраняется).
4. Нажать «📥 Получить узлы из Mihomo».
5. PASS: статус «✔ Список узлов получен…»; сводка «Источник: Mihomo runtime · Провайдеров: N ·
   Узлов: N · Уникальных имён: N · Обновлено: …»; узлы появились в общем списке.
6. FAIL-диагностика (безопасно, secret через переменную окружения, не в историю shell):
   ```sh
   export MIHOMO_SECRET='...'   # вставляется интерактивно, не хранить в истории
   curl -sS -H "Authorization: Bearer $MIHOMO_SECRET" http://<controller>/providers/proxies -o /tmp/providers.json -w '%{http_code}\n'
   ```
   - `200` → браузерная проблема (CORS/разрешение локальной сети) → путь 4C;
   - `401/403` → secret/права контроллера;
   - таймаут → адрес/listen/сеть.
   Ответ `/providers/proxies` НИКУДА не загружать.

### 4C. Paste / upload fallback (если 4B не прошёл)
1. В соседней вкладке браузера или через curl (4B) открыть
   `http://<controller>/providers/proxies` и сохранить JSON в локальный файл.
2. «📄 Загрузить .json» (или «📋 Вставить JSON» из буфера).
3. PASS: «✔ Runtime JSON разобран (paste/upload)»; тот же список/сводка, что в 4B.

### 4D. Контракт импорта
1. После импорта нажать «✖ Очистить runtime-список» → PASS: runtime-часть ушла, preview-имена
   (если были) вернулись.
2. Перезагрузить страницу → PASS: адрес контроллера и secret пусты (не персистятся);
   localStorage не содержит секретов (см. §8).

## 6. TIERED FAILOVER на живом Mihomo (#148/#165)

Топология: минимум два эшелона; Tier 1 — здоровый рабочий выход, Tier 2 — заведомо
рабочий резерв (например другой WG/AWG-профиль). НЕ использовать сценарии, ломающие
продакшн-доступ (не отключать единственный канал).

1. Включить «🪜 Приоритетные эшелоны выходов», Tier 1 = рабочий выход, Tier 2 = резерв;
   Build → `mihomo -t` → развернуть.
2. **A (Tier 1 живой)**: в дашборде группа «🪜 TIERED-AUTO» выбрала Tier 1-группу; трафик идёт
   через Tier 1. PASS.
3. **B (отказ Tier 1)**: безопасный обратимый способ — в дашборде вручную остановить/
   отвязать узлы Tier 1 (или временно выключить только узлы Tier 1 на сервере). Подождать
   health-интервал (в конфиге 300 ms interval + lazy:false, практически секунды).
   PASS: «🪜 TIERED-AUTO» переключился на Tier 2; трафик идёт. Записать ≈время переключения
   (наблюдение, НЕ SLA).
4. **C (failback)**: вернуть Tier 1. PASS: группа вернулась на Tier 1. Записать ≈время.
5. **Race fix (#165), без роутера**: в генераторе открыть карточки эшелонов, в списке
   прокси набрать/изменить текст (вызывает перерисовку реестра целей), затем выбрать
   участника в селекте карточки и нажать «＋». PASS: выбранный участник добавился (выбор не
   потерялся после перерисовки).
6. UDP не проверять и не заявлять (провобы только HTTP).
