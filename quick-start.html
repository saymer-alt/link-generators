Быстрый старт

Простыми словами: что нажимать, чтобы получить рабочий конфиг Mihomo. Ключи и WG/AWG-файлы обрабатываются локально. Если вы используете HTTP(S) подписку, при Build браузер может запросить её для preview имён/статического разворачивания; при проблемах CORS runtime может использовать публичный fallback-прокси для чтения подписки.

Шаг 1. Где будет работать Mihomo?

Наверху вкладки Builder есть вопрос «🎯 Где будет работать Mihomo?» — это профиль развёртывания. Он задаёт «сценарий»: что включить и что выключить. Прокси, подписки и файлы он не трогает.

🏠 Роутер / обычный TUN (Keenetic) — по умолчанию

  • Когда: Mihomo стоит на домашнем роутере (Keenetic с Entware) или на компьютере, и нужно «завернуть» весь трафик устройства.
  • Включает: TUN-интерфейс (весь трафик через Mihomo), MIPS-стек, порт 7890, доступ из локальной сети.
  • Чего не делает: не настраивает сам роутер — установка Mihomo на Keenetic описана в проекте keenetic-auto-setup.

🖥️ VPS — локальный Mihomo / SOCKS для Xray / 3X-UI

  • Когда: на сервере уже работает Xray/3X-UI (или другое приложение), и оно отправляет трафик в Mihomo через 127.0.0.1:7890.
  • Включает: только локальный вход 7890; TUN и «доступ из сети» выключены — они серверу не нужны.
  • Чего не делает: не настраивает Xray/3X-UI — в панели укажите исходящим сервером socks5://127.0.0.1:7890.

🌐 VPS Transparent Gateway (amnezia-mihomo-gateway)

  • Когда: специальный сценарий «прозрачного шлюза» с Linux-маршрутизацией, Docker и AmneziaWG — всё под управлением amnezia-mihomo-gateway.
  • Включает: TUN с фиксированными настройками безопасности, DNS-перехват (fake-ip) с полями ниже, автоматический пакет домен-детекта.
  • Чего не делает: никогда не настраивает Linux-часть (маршруты, firewall, Docker) — это делает установщик gateway. Для обычного VPS с Xray выбирайте предыдущий профиль.

Шаг 2. Что вставить

Всё вводится в одно поле «Основные прокси-ссылки / URL-подписки»; режим подписок подбирается под содержимое.

Что у вас естьЧто делать
Обычные ссылки vless://, trojan://, ss://, masque://…Вставьте в большое поле; режим «📡 Использовать URL-подписки» выключите.
Ссылка-подписка https://…Вставьте в то же поле. Режим «📡 Использовать URL-подписки» включён — получите динамический provider; выключен — генератор один раз скачает текущие узлы и встроит их как статические proxies:.
Файлы WireGuard / AmneziaWG .conf/.wg/.awgКнопка «➕ Загрузить .conf / .wg / .awg» — файлы добавляются к уже загруженным; загруженные профили видны списком (удалить один — «✕», все — «🧹 Очистить все»). Идентичный файл повторно не добавляется.
Свои WARP-ссылкиВкладка «⚡ WARP MASQUE Links»: вставьте WARP YAML (бот или WARPSCOUT/Mihomo MASQUE) → «Сгенерировать» → «🚀 В Mihomo Builder».
Смесь (подписка + ссылки)Можно вместе в обоих режимах: при включённом URL останется provider, при выключенном URL развернётся в статические узлы, а обычные ссылки сохранятся.

Шаг 3. Типовые сценарии

Каждый сценарий — отдельная карточка: что включить → что вставить → что нажать → что получится.

1. Обычные ссылки на Keenetic

  1. Профиль «🏠 Роутер» (уже выбран).
  2. Вставьте ссылки, выключите «📡 URL-подписки».
  3. «⚡ Build Config» → «📋 Copy YAML».
  4. Готовый config.yaml с TUN-режимом — на роутер.

2. URL-подписка

  1. Профиль «🏠 Роутер»; режим «📡 URL-подписки» включён.
  2. Вставьте URL подписки. Узлы фильтруются опциональным «🚫 Exclude Filter» (для кириллических имён пишите фильтр кириллицей: Россия|Москва).
  3. «⚡ Build Config» → Copy. Mihomo сам скачает и будет обновлять узлы (раз в 12 часов + проверка доступности).

3. WARP / AmneziaWG

  1. WARP: вкладка «⚡ WARP MASQUE Links» → WARP YAML (бот или WARPSCOUT/MASQUE) → «Сгенерировать» → «🚀 В Mihomo Builder».
  2. AWG: «➕ Загрузить .conf / .wg / .awg». Если в файле DNS 100.64.0.1 — подставятся публичные (с предупреждением).
  3. «⚡ Build Config» → Copy. Несколько файлов станут несколькими WireGuard-прокси. Каждый файл проверяется отдельно — невалидный не попадёт в сборку (имя и причина будут в списке под менеджером).

4. Xray → локальный Mihomo на VPS

  1. Профиль «🖥️ VPS — локальный Mihomo / SOCKS».
  2. Вставьте ссылки/подписку как в сценарии 1–2.
  3. «⚡ Build Config» → Copy. В Xray/3X-UI укажите исходящим socks5://127.0.0.1:7890.

5. Transparent VPS Gateway

  1. Профиль «🌐 VPS Transparent Gateway». Проверьте поля (TUN device, MTU, fake-ip-range) — они должны совпадать с установщиком gateway (обычно менять не нужно).
  2. Вставьте прокси/подписки; при желании включите «🚦 Политики по доменам».
  3. «⚡ Build Config» → Copy → установите через amnezia-mihomo-gateway (он сам настроит Linux-часть).

6. Политики по доменам (DPR)

  1. Включите «🚦 Политики по доменам», нажмите «➕ Добавить политику», выберите шаблон (AI/YouTube/Telegram/Google/Direct) или впишите свои домены (по одному в строке).
  2. «⚡ Build Config» → Copy. Домены из категории пойдут через отдельную группу выхода; остальной трафик — как раньше (MATCH,GLOBAL).
  3. Состав подписки меняется — правила пересобирать не нужно: правила указывают на группы, группы — на подписку.

7. Автоматический режим белых списков (БС)

  1. Включите «Автоматический режим белых списков».
  2. В верхнем поле — обычные серверы (основные), в появившемся втором — резерв (то, что работает при блокировках).
  3. «⚡ Build Config» → Copy. При недоступности основных выходов Mihomo сам перейдёт на резерв и вернётся обратно по проверке доступности.

8. WARP через промежуточный VPS (dialer-proxy)

  1. Загрузите WARP как в сценарии 3.
  2. В карточке загруженного профиля выберите «Подключение: Через промежуточный proxy» и таргет в списке «Промежуточный выход» — он содержит только реально существующие в конфиге цели (точные имена, включая суффиксы дублей); вводить имя вручную не нужно. У каждого профиля свой выбор: один — «Напрямую», другой — через транзит.
  3. Состав dialer-группы (имя + транзитные узлы + URL-подписки) задаётся полями ниже карточек — это «определение группы»; кто её использует, решает каждая карточка.
  4. «⚡ Build Config» → Copy. WARP будет подключаться к Cloudflare через выбранный транзит (другая страна/сеть).
  5. Важно: транзитный узел обязан поддерживать UDP; смена узла в группе меняет путь не мгновенно (до ~150 секунд) — для мгновенной смены нужен reload конфига.

Сохранение и проверка перед переносом

Новая доменная политика добавляется в конец списка: шаблон AI получает свободное имя AI, AI-2, AI-3… Карточка прокручивается в видимую область, фокус переходит в название. Порядок существующих политик сохраняется и определяет приоритет правил. MagiTrickle импортируется отдельной кнопкой.

В графах Builder и Config Studio доступны «−», «+», «100%» и «Вписать граф». Перетаскивайте пустую область для перемещения; Alt + колесо меняет масштаб графа, обычное колесо прокручивает страницу. Клик или Enter на узле включает фокус, «Весь граф» возвращает обзор. Полные подписи доступны в текстовой альтернативе.

Пустой адрес runtime-controller означает http://192.168.1.1:9090, запрос выполняется только кнопкой Fetch. Полный URL панели /ui/#/overview распознаётся автоматически; пользовательский API-префикс сохраняется. Перед отправкой API secret на адрес по умолчанию требуется подтверждение. При сетевом отказе точную причину смотрите в DevTools (F12 → Console); JSON можно импортировать вручную.

Inspector с пустым полем проверяет gemini.google.com, не вписывая его в поле и не обращаясь к домену по сети. До Build или после изменения настроек Inspector и Coverage предлагают собрать актуальную конфигурацию и продолжить проверку. Если ввод содержит URL-подписки, перед потенциальным сетевым действием запрашивается подтверждение. Это офлайн-анализ YAML, не доказательство фактического маршрута.

В Studio «Сбросить все правки» возвращает и операции, и несохранённые поля к исходному YAML. Clear или новый Parse отменяет применение читаемого старого YAML-файла. В runtime import очистка/новый импорт отменяет поздний ответ; запрос к controller имеет тайм-аут 8 секунд, после него можно повторить запрос или загрузить JSON локально.

Перед редактированием сохраните проект .lgproject.json: он сохраняет исходные ссылки, профили и настройки. Файл содержит рабочие секреты — храните его локально. При загрузке сначала проверьте Preview; Cancel сохраняет текущий Builder, Confirm применяет проект, затем нужен Build.

Восстановление из YAML имеет явные ограничения: исходные ссылки развёрнутых подписок и произвольные поля не всегда восстановимы. Проверьте отчёт Reverse Preview; для точного продолжения работы используйте сохранённый проект. Пресеты DPR с отдельной SELECT-группой сохраняют её имя при поддерживаемом Reverse.

В сводке Studio DNS включён только при dns.enable: true; пустая секция DNS не включает его. Статические графы и диагностики показывают намерение конфигурации. Рабочий DNS, handshake и реальный маршрут проверяются отдельно на вашем устройстве.

Частые вопросы

Короткие ответы на то, что чаще всего спрашивают.

Проверка прошла, а Mihomo не запускается с конфигом

Базовая проверка в браузере ловит только очевидные структурные ошибки. Авторитетная проверка — на машине с Mihomo: mihomo -t -f config.yaml. Если реальный Mihomo отверг YAML — сохраните полный YAML и полный вывод команды.

Общий DNS override для WG/AWG — что это

Поле «Общий DNS override для всех WG/AWG профилей» применяется ко всем загруженным WireGuard/AmneziaWG-профилям сразу (добавляет dns/remote-dns-resolve в каждый из них). Пусто — DNS удаляется из профилей. Задать DNS отдельно для одного профиля нельзя.

Подписка отдаёт «App not supported» / пустой список

Некоторые панели требуют заголовок x-hwid — генератор добавляет его автоматически, причём один и тот же для preview-запросов и для всех провайдеров конфига (один логический объект = одна идентичность устройства; второму роутеру создайте идентичность кнопкой «➕ Новое устройство»). Если панель всё равно отказывает, проверьте, что подписка активна и ссылка полная.

Панель подписки видит несколько устройств вместо одного

Идентичность устройства теперь одна для всего конфига и не меняется при пересборках. Ранние версии могли создавать отдельный HWID на каждого провайдера — после обновления сгенерируйте конфиг заново: новые сборки используют единую идентичность. Device Model — просто подпись, на идентичность она не влияет.

Как посмотреть список серверов подписки

Включите «📋 Показать серверы подписки» (в блоке основных переключателей) и нажмите «Получить список»: появится поиск и выбор узлов галочками (отмеченные станут исключениями). Переключатель по умолчанию выключен — без него подписка браузером не запрашивается.

Один из WG/AWG-файлов не загружается

При загрузке нескольких WG/AWG генератор проверяет каждый файл отдельно. Невалидный файл не попадёт в сборку; его имя и причина будут показаны под списком. Для клиентского WG-профиля Peer обычно должен содержать Endpoint = host:port. Если в файле нет Endpoint, это может быть серверный WireGuard-конфиг — генератору нужны клиентские профили.

Exclude Filter не исключает «Россия»

Фильтр сравнивается с фактическим именем узла: латинский ru|russia не совпадёт с кириллическим «Россия». Пишите оба варианта.

Что делает «?» рядом с настройками

Короткая подсказка «что это и когда включать». Наведите мышью, коснитесь пальцем или выберите с клавиатуры (Enter — открыть, Escape — закрыть). Значения настроек она не меняет.

Нужна ли кнопка «🖥️ Web UI»?

Она скачивает веб-панель управления Mihomo (MetaCubeXD по умолчанию). Для «поставил и работает» — не обязательна, но удобна для смены узлов и просмотра логов.

Какая версия Mihomo нужна

Минимум — 1.19.31 (для MIPS-стека TUN и домен-детекта gateway), рекомендуемая — 1.19.32. Отдельные функции имеют собственные минимумы (AWG 3.1 — от 1.19.30, политики по доменам — от 1.19.27); подсказка у переключателя предупредит, если функция требует новее.

Config Studio 2.0: восстановление Builder (v1.11-dev)

«Сохранить проект» скачивает приватный .lgproject.json с ключами и токенами. «Загрузить проект» показывает счётчики и сравнение, затем требует подтверждение даже в новой сессии. Отмена ничего не меняет; Undo возвращает прежнее состояние после применения. Не публикуйте проект.

Готовый YAML: Config Studio → «Разобрать» → «Восстановить в Builder». Предпросмотр ничего не меняет. Прочитайте потери и сравнение: подписки, прямые ссылки, WG/AWG и UNKNOWN считаются отдельно. CONFLICT/INVALID требуют исправления исходника. WG dialer на прямой узел, который не переносится в Builder, блокирует восстановление; используйте исходный проект или редактор YAML. MISSING не восстановлен; UNSUPPORTED сохраняется в проекте и исходном YAML, но не попадёт в новый Build.

Подтвердите понимание потерь → «Подтвердить восстановление», либо «Отмена». Изменение YAML или Builder требует нового предпросмотра. После Apply доступен Undo. В редакторе 👁 меняет только видимость секрета, сохраняя введённое значение; Save применяет его.

DNS ↔ Routing (v1.11-dev, интегрирован в main)

В Config Studio после «Разобрать» откройте DNS ↔ Routing. Это локальный статический snapshot: изменений YAML и запросов к DNS-серверам нет. После правок повторите «Разобрать»; «Очистить» удаляет snapshot.

CONFIRMED — структурная ошибка по исходникам Mihomo; INFERRED — возможное влияние различия DNS/data paths; UNKNOWN — недостаточно информации. DNS без явного enable: true выключен. HTTPS/TLS/QUIC — транспорт, не доказательство проксирования; fragment #PROXY выбирает известный селектор, реальный member группы неизвестен. Правило с PASS пропускается при поиске следующего маршрута. В mode: direct/global сравнение DNS с доменными правилами имеет статус UNKNOWN: эти правила не выбирают путь данных. GEOSITE/RULE-SET и сеть не наблюдаются; отсутствие предупреждения не доказывает отсутствие утечки.
